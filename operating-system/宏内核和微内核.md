1.宏内核和微内核的区别
	宏内核通常是作为一个单一的、巨大的程在内核状态下运行，其其所有服务运行在同一个内核地址空间内，这也正是其高性能但高风险的原因。而微内核则让内核执行一些基本的功能，如基本调度和进程间通信，其他服务由守护进程(也称为服务器)提供，这些进程和其他应用程序都在用户态下运行。目前主流的linux发行版都使用宏内核，且大量的UNIX系统，例如BSD家族，也是使用宏内核
2.核心定义与架构区别
	操作系统的内核是连接硬件与上层软件的"桥梁"。根据内核提供的服务器数量和运行方式，主要分为宏内核和微内核两大流派
		宏内核(Monolithic Kernel):又称单内核。操作系统所有的核心服务(如进程调度、内存管理、文件系统、设备驱动、网络协议栈)都集成在同一个内核地址空间中，全部运行在内核态(Ring 0).
		微内核(Microkernel):秉持"最小核心"原则。内核只保留最基础的功能(如进程间通信IPC、基础调度、地址空间管理)，而将文件系统、驱动、网络协议栈等作为普通的用户态守护进程/服务器运行
3.核心机制与优缺点对比

| 对比维度   | 宏内核(Monolithic Kernel)                        | 微内核(Microkernel)                        |
| ------ | --------------------------------------------- | --------------------------------------- |
| 通信方式   | 函数调用(直接调用)。类似在同一间屋子里面交流，零延迟                   | 进程间通信(IPC/消息传递)。类似在不同房间内通过信使传话，有延迟      |
| 性能表现   | 极高。无上下文，适合高性能计算                               | 相对较低。频繁的用户态/内核态切换及IPC拷贝会带来性能损耗(即微内核性能税) |
| 稳定性    | 极差。任何一个驱动(如显卡驱动)崩溃，都会导致整个系统内核崩溃(Kernel Panic) | 极高。驱动/服务器崩溃仅是该进程退出，内核毫发无伤，可热重启该服务       |
| 扩展性与维护 | 困难。代码耦合度极高，新增硬件需修改整个内核，重新编译内核后才能生效            | 简单。添加新功能只需新增一个用户态服务，无需重启系统，模块间隔离清晰      |
| 典型代表   | Linux、BSD家族(FreeBSD/OpenBSD)、macOS的XNU内核(有争议) | QNX(车载系统)、Minix、seL4(高安全认证)             |
4.宏内核和微内核他们之间和用户态的联系，或者说是怎么调用的
对比表

| 对比维度      | 宏内核                            | 微内核                                                |
| --------- | ------------------------------ | -------------------------------------------------- |
| 用户态里有     | 普通的应用程序                        | 应用程序(App)+操作系统服务/驱动(Servers)                       |
| 内核态里有什么   | 绝对核心：调度、内存、文件系统、驱动、网络协议栈(几乎全部) | 最小核心：仅IPC(进程间通信)、基础调度、地址空间机制                       |
| 用户态如何"求助" | 系统调用(System Call)--直接“翻墙”进内核   | IPC消息传递(Message Passing)--先找“邻居(服务进程)”，再有邻居决定是否找内核 |
| 调用时的“过门费” | 1次上下文切换(用户态->内核态->用户态)         | 多次上下文切换(App->服务进程->内核->服务进程->App),开销较大             |
